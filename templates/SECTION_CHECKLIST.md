# One-section completion checklist

Copy this checklist alongside the [section brief](SECTION_BRIEF.md). Leave an item open when it is incomplete. Mark an irrelevant item N/A with a reason; do not count it as a passed check.

## Before building

- [ ] Read the current focus, relevant decisions and existing work.
- [ ] Define one user outcome and the reviewed starting version.
- [ ] State included work, exclusions, limits and current authority.
- [ ] Resolve blocking choices; record assumptions that remain.
- [ ] Confirm prerequisites in the intended environment.
- [ ] Write observable acceptance criteria, including relevant failure paths.

## During the section

- [ ] Implement within the agreed scope.
- [ ] Check the behavior in the required setting.
- [ ] Inspect the resulting state and relevant repetition/timing behavior.
- [ ] Verify preserved behavior where the change could affect it.
- [ ] Record important discoveries, decisions and their reasons as they happen.
- [ ] If conditions exceed a limit, stop dependent action and resolve the exact change.

## Before calling the section complete

- [ ] Map every required criterion to evidence or an explicit limitation decision.
- [ ] Keep local, simulated, external and physical-device results distinct.
- [ ] State failures, skipped checks and unverified behavior.
- [ ] Obtain the responsible reviewer's acceptance where required.
- [ ] Save and read back a concise handoff and update the current focus.
- [ ] Report the result and proposed next section within its authority boundary.

## Before publishing, if publishing is in scope

- [ ] Confirm destination, visibility and authority for the exact content.
- [ ] List and manually review every file being published.
- [ ] Exclude private source/notes/plans and personal or operational details from public teaching material.
- [ ] Exclude credentials and signing/recovery material from every repository.
- [ ] Scan the proposed change; for public Git publication, scan the working files and full history being pushed.
- [ ] Check links and evidence claims without treating scans as a security guarantee.
- [ ] Compare uploaded content and remote revision with the reviewed version.
- [ ] Check for unpublished changes and report any remaining gap accurately.

Completion applies to the named section and accepted scope. It does not automatically authorize a new section, external action or production release.
